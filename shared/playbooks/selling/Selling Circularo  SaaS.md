# **Selling Circularo SaaS**

This document provides practical sales rules for selling Circularo consistently and correctly. It explains what to sell, how to position our products, how to choose the right commercial model, and what commitments sales must never make. It complements the **Circularo Commercial Model**, which remains the authoritative source for all licensing and commercial policies.

* Circularo is a Digital Trust Platform
* End-to-end platform
* More than eSignatures
* Two sales motions:
    * Trusted Execution (SaaS)
    * Sovereign Trust Services (Self-Hosted)

## **1\. Always sell Solutions, not features**

Customers buy outcomes.

Never start with Editions, Plans or Add-Ons.

Always start with:

What business problem are you trying to solve?

Examples:

* Digital Customer Onboarding  
* Internal Approvals  
* Government Shared Signing  
* Contract Lifecycle  
* Trusted Document Archive

Features come later.

---

## **2\. Sell Products**

Customers buy Products.

Examples:

* Circularo Business  
* Circularo Enterprise  
* Circularo Ultimate

Never sell Editions.

Editions are internal technical concepts.

---

## **3\. Plans determine pricing**

Never invent pricing.

Never invent bundles.

Never promise exceptions.

Every quote must map to an approved Plan.

---

## **4\. Never mix licensing models**

Every subscription is either:

* User-Based  
* Transaction-Based  
* DMS-Only

Never combine them within the same subscription.

If a customer needs a different model, migrate them instead.

---

## **5\. Choose the licensing model based on customer behaviour**

### **Sell User-Based when:**

- Employees regularly work in Circularo
- Internal users are the primary users
- Pricing is best aligned with licensed users
- API may be used for automation and integration

### **Sell Transaction-Based when:**

- Transaction volume is the primary pricing driver
- Large numbers of external recipients
- High-volume automation
- Embedded applications
- API integrations  
- Automation  
- Batch processing

Never sell User-Based simply because it appears cheaper.

---

## **6\. API is never included**

REST API Access always requires the REST API Access Add-On.

REST API Access enables platform integration only.

Programmatic trust services require the corresponding Consumption Add-Ons, such as:

- API eSigning Transactions
- API eSealing Transactions
- Identity Verification
- SMS OTP
- Qualified Timestamp

Never tell customers:

“Unlimited means unlimited.”

It does not.

---

## **7\. Unlimited does not mean unlimited**

Unlimited Transaction plans apply to manual transactions performed by licensed Internal Users.

They do not include:

- Automated API signing
- Automated API sealing
- Batch processing
- System-generated workflows or trust services

These require the corresponding API Transaction Add-Ons.

---

## **8\. Trust services are never included**

Do not assume:

* SMS OTP  
* KYC  
* National ID  
* UAE Pass  
* Nafath  
* Qualified Signatures  
* Qualified Seals  
* Qualified Timestamp  
* SMS reminders

These are separate Add-Ons unless explicitly included in a commercial offer.

---

## **9\. Storage is the most common misunderstanding**

Always explain:

Transactional documents

✔ Always archived.

✔ Always retained.

✔ Included.

Standalone document management

❌ Not included.

Requires:

* DMS & Archiving Add-On

Additional storage never replaces DMS.

---

## **10\. Don’t sell Add-Ons individually**

Add-Ons extend an existing subscription.

They are not standalone products.

Always start with:

Plan → Subscription → Add-Ons

Never the other way around.

---

## **11\. Never promise features outside the customer’s Plan**

If the Plan doesn’t support it:

Don’t promise it.

Upgrade the customer instead.

---

## **12\. One customer \= one subscription model**

Keep commercial models simple.

Avoid custom combinations.

Avoid hybrid licensing.

If an exception is needed:

Escalate.

---

## **13\. Support is a commercial item**

Essential Support is included.

Standard, Plus and Premium are upgrades.

Never include Premium Support “for free.”

---

## **14\. Self-hosted is Ultimate only**

Never sell:

Self-hosted Business

Self-hosted Enterprise

Only Ultimate supports self-hosting.

---

## **15\. Commercial model is not negotiable**

Sales may negotiate:

* Discount  
* Contract term  
* Volume  
* Commercial incentives

Sales may not change:

* Licensing rules  
* Subscription models  
* Product definitions  
* Add-On rules  
* Commercial structure

---

# **Things Sales Must Never Say**

❌ “API is included.”

❌ “Unlimited means unlimited.”

❌ “We’ll just give you that feature.”

❌ “We’ll combine user and transaction licensing.”

❌ “Storage is unlimited.”

❌ “Qualified signatures are included.”

❌ “SMS OTP is included.”

❌ “We’ll figure out licensing later.”

---

# **Sales Decision Tree**

1. What business problem are we solving?  
2. Which Product fits?  
3. Which Plan fits?  
4. User-Based or Transaction-Based?  
5. Which Add-Ons are required?  
6. Which Support level?  
7. SaaS or Ultimate (self-hosted)?  
8. Generate quote.
