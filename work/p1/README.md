# Circularo Sales Narrative — P1 Content Package

## Purpose

This directory contains the reconciled content architecture for the Circularo company narrative and four sales-deck applications. It is the content-approval stage: the narrative, sequence, and audience-facing copy are defined here before any visual slide production begins.

The package consolidates the working material in `work/ideas/` and the direction in `work/observations.md`. Those source files remain unchanged.

## Working status

This is internal working material, not a governed or externally approved source. “Canonical” within this package means the single working narrative from which the four deck applications are derived. It does not override repository governance or turn draft, inferred, or unsupported claims into approved facts.

## Communication architecture

The shared narrative is:

> Autonomy increases the burden of trust. Intelligence does not create authority. Circularo connects identity, authority, policy, collaboration, approval, execution, and evidence in a continuous trust chain. Trusted execution creates trusted records; trusted records create institutional memory; institutional memory provides governed context for AI. The same trust capabilities can serve people, organizations, applications, and AI agents through a programmable trust layer.

The four applications answer different buyer questions:

| Deck | Buyer question | Primary outcome |
| --- | --- | --- |
| Company | Why does Circularo exist? | Understand the category, strategic role, and long-term relevance of Circularo. |
| SaaS | Why should our organization use Circularo? | Choose a managed path from fragmented digital work to trusted execution. |
| Sovereign | How can we achieve this while retaining control? | Define a customer-controlled trust boundary and operating model. |
| Shared Services | Why establish this once for an entire government or ecosystem? | Explore shared sovereign trust infrastructure across many entities. |

## Narrative discipline

The visible deck architecture follows the content logic:

> Autonomy → Trust gap → Fragmentation → Trusted execution → Evidence → Institutional memory → Trusted AI → Governed action

The earlier sales framework remains an internal quality check:

1. Does the deck create a useful insight?
2. Does it expose the limitations of current alternatives?
3. Does it establish a credible ideal state?
4. Does it make Circularo's role clear?
5. Does it explain meaningful differentiation?
6. Does it provide approved proof?
7. Does it address the audience's real concerns?
8. Does it end with a specific next step?

## Boundary for the next phase

Before these files are used for external slides, the accountable owners should approve the terminology and close the evidence requirements listed under `review/`. Visual production should then use these files as the content source, without re-opening the core narrative unless review identifies a substantive issue.
